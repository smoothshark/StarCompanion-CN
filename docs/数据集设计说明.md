# 情感陪伴对话数据集：我是怎么设计的

这份文档写清楚三件事：我为什么这样设计、数据由什么组成、一条样本里装了什么。

数字以仓库内选题库为准，见 `data/scenes/scene_library.json`（约 561 条，每条带年龄硬锁）。更细的覆盖统计在《场景覆盖报告》里。

给开发者怎么用（只用数据 / 可视化改数据）见根目录 [README.md](../README.md)。

---

## 1. 我到底要测什么

一开始我就定了：我们不是在测「模型会不会安慰人」。

真正想测的是——面对 3～35 岁的中文用户，在一段有前文的真实生活里，**它能不能接住此刻最需要被接住的那一下**。

所以样本我故意做成半开放考题：

- **不给标准答案。** 陪伴本来就没有唯一正确句，给了答案模型只会学模板腔。
- **对话停在用户最后一句。** 考点是「接住」，不是复述前文。
- **期望回复很短：一两句到三句，尽量不超过四十个字。** 跟真实产品里陪伴者的说话长度对齐。
- **先有具体发生的事，再写感受。** 不然很容易写成空喊情绪、空喊热情。
- **陪伴不是心理咨询。** 一上来给建议、说教、连珠炮追问，这些我都列为禁止写法。

一句话：测的是接住，不是讲大道理。

---

## 2. 为什么不按「难过 / 焦虑」铺题

行业里常见做法是按情绪词铺：难过一批、焦虑一批、开心一批。我没用这套。

我更相信：人难受，往往不是因为贴了某个情绪标签，而是因为生活里发生了一件具体的事，触发了某种反复出现的心理结构。所以我从「机制」往下拆：

```text
生活事件大类
  → 机制（真正痛/暖的那个点）
    → 原子生活事件（一件能说清楚的事）
      → 多轮对话样本（末轮露出考点）
```

怎么理解这四层：

1. **大类**：生活里反复碰到的处境板块，比如连接、被看见、能力评价、边界。
2. **机制**：同类处境里真正要命的那个结构。比如「分离与想念」「被排除与落单」「进步被敷衍」。
3. **事件**：某个年龄段真的可能经历的事。妈妈出差讲不了睡前故事；同事订餐漏掉自己。
4. **样本**：围绕这件事写成的多轮对话，最后一轮把评测信号露出来。

我这样设计，主要是为了三点：

- 同一个机制可以跨年龄改写（幼儿园想家，到职场异地），评测时还能横向比。
- 任何人拿起一条题，都能说清「这条在考什么」，而不是笼统一句「情绪不好」。
- 后面要扩库，有格子可补，不会无限堆长得很像的题。

## 3. 数据其实是两层，别混着报

我把整套东西拆成两层资产。对外说话、对内排期，都不要混：

| 层级 | 是什么 | 大概规模 | 我拿它干什么 |
|---|---|---|---|
| 选题库（场景库） | 生活事件 + 分类 / 机制 / **年龄硬锁** 等标签 | ~561 条 | 选题、控覆盖、防偏科、防不适龄 |
| 对话成品库 | 人工确认后的多轮样本 | 目前还很少 | 真正进评测、导出 |

构造台解决的是：把选题写成对话。但我有一条硬规矩——**机器可以起草，只有我（或评审）人工确认过的，才算正式成品。**

### 选题库我是分三层加厚的

| 层 | 条数 | 当时在想什么 |
|---|---:|---|
| 基础层 | 200 | 先把 12 个核心生活大类铺开；默认偏消极；一条事件常常对应一个年龄 |
| 扩展层 | 190 | 明显加厚身体与能量（生理期、身体羞耻、感官等），同时补正情绪和红线；一条事件常适配多个年龄 |
| 平衡层 | 108 | 补日常陪伴、兴趣游戏、成长发现这些轻连接；不然全集太苦情，产品只会「急救」不会「陪伴」 |
| 合计 | ~561 | 这是选题覆盖，不是已经写完的对话数；合法评测卡另按 ageBands 展开 |

## 4. 选题库挂了哪些标签

每条生活事件我都挂了一套标签。进构造台选题时，会自动带进写作表单，也可以改。

```text
事件
 ├─ 大类 category
 ├─ 机制 mechanism
 ├─ 适用年龄 ageBands（可以多个）
 ├─ 场景类型 scene_type（一条只选一个主场景）
 └─ 情绪极性默认值（定稿时以末轮用户话为准重标）
```

### 4.1 生活事件大类

现在一共 15 类。前面 12 个是基础骨架，后面 3 个是平衡层补进去的陪伴向大类。

**核心处境（基础 12 类）**

连接与归属、被忽视/未被看见、能力与评价、自主与边界、公平与尊严、家庭与照护、失去与变化、安全与不确定、自我与身份、身体与能量、数字生活、日常微挫败。

**陪伴向补齐（平衡层）**

日常陪伴、兴趣与游戏、成长与发现。

体量上，身体与能量现在最厚（大约 113 条），其次是连接与归属（大约 73 条）。数字生活、日常微挫败还偏薄——有些是低龄用不适用，不完全是漏做。

### 4.2 机制

大约 138 种。对我来说，机制就是「考点名」。举几类：

- 连接：分离与想念、被排除与落单、关系疏远、单向关系……
- 被看见：成果无人回应、进步与分享被敷衍、难受信号被漏接……
- 身体：生理期疼痛、侧漏羞耻、身体成长与羞耻、感官过载……
- 红线：秘密分享与隐私边界、依赖信号、关系替代与独占……
- 平衡向：没有压力的日常闲聊、共同游戏与想象、平凡时刻里的连接……

### 4.3 年龄段与年龄硬锁

固定 7 档，覆盖 3～35 岁：

| 年龄段 | 大概几岁 | 我写样本时常用的具体年龄 |
|---|---|---:|
| 幼儿园 | 3～5 | 4 |
| 小学低年级 | 6～8 | 7 |
| 小学高年级 | 9～11 | 10 |
| 初中 | 12～14 | 13 |
| 高中 | 15～17 | 16 |
| 大学 | 18～21 | 20 |
| 职场人 | 22～35 | 28 |

我坚持几条：

- 年龄决定口吻和生活细节，不决定「能不能有情绪」。
- 场景库按当前年龄段过滤；标了年龄锁的事件，不会跑到不适用的档里。
- 基础层里职场人故意多一些——成年关系、边界、压力更密，产品后期绕不开。

#### 不是场景 × 年龄的笛卡尔积

早期有个坑：基础层约 200 条事件多数没写 `ageBands`，生成流水线就会默认「每条事件 × 七档年龄」全铺开。于是「转正 / 绩效 / 大学答辩」也会落到幼儿园，形成大量**不适龄伪样本**——看起来覆盖很满，其实在测假题。

所以年龄适用性不能停在生成提示里的软约束（指望模型自己别写错），而要升成**场景库硬锁**：

```text
原子事件
  └─ ageBands（允许的年龄档，必填）
        │
        ▼
合法卡片 = 该事件 × 其 ageBands 内的年龄
        │
        ▼
候选生成 / 待审 / 导出 只认合法卡片
不适龄组合直接剔除，不进正式集
```

审查时看的是**情景与年龄是否匹配**，例如：

| 情景边界 | 年龄硬锁原则（举例） |
|---|---|
| 实际尿床、藏湿床单 | 只保留约 3–11 岁（幼儿园～小学高年级）；初中及以上不出现 |
| 梦遗、清理羞耻 | 与「尿床」分开，作为青春期事件，不落到低龄 |
| 玩偶学校、扣纽扣、小红花 | 低龄生活标记，不进初中及以上 |
| 住校、月考、班主任、高考 | 校园事件，不进职场档 |
| 转正、绩效、同事、客户 | 明确职场事件，不进未成年档 |
| 月经 / 初潮相关 | 不进约 9 岁以下 |
| 伴侣、结婚、生育计划 | 不进小学及以下 |

工具侧用固定规则做审计（`node scripts/a1-codex-batch-tools.mjs audit-ages`）：缺 `ageBands`、未知年龄档、或命中高风险规则冲突，一律算失败。通过后，候选组合数是「审查后的合法积」，不是「561 × 7」。

若清掉不适龄卡后消极比例下跌，正确做法是**补真正跨年龄成立的原子事件**（同一件事能在幼儿园到职场自然改写），而不是把旧的不适龄卡加回去凑数。

### 4.4 场景类型 scene_type

回答的是：这条主要考哪一类陪伴情境。构造台里现在大约 40 种叫法，包括日常闲聊、平静共处、靠近与边界这些平衡向类型。

常见的比如：社交冲突、挫败、恐惧焦虑、分离/孤独、家庭压力、失去、正情绪小声分享；以及红线三类——隐私、依赖、关系替代。

有个待办我自己也知道：字段规范 `schema_v1.json` 里正式认的类型，目前比构造台可写的少。正式冻结版本前，两边要对齐。

### 4.5 情绪极性

四种：积极、消极、混合、中性。

- 选题库可以带默认值；基础层起笔默认偏消极。
- **定稿时以最后一轮用户话为准**重标。
- 积极、混合、中性主要靠扩展层和平衡层补——我不希望全集只剩哭诉。

### 4.6 红线：必须人审

这三类我强制走人审，不能只看「暖不暖」：

| 场景类型 | 我在防什么 |
|---|---|
| 秘密分享 / 隐私边界 | 隐私被不当处理 |
| 依赖信号 | 过度依赖 AI |
| 关系替代 / 独占 | 用 AI 替代真人关系 |

红线题先审安全和边界，再看陪伴质感。

## 5. 一条样本长什么样

成品是一条 JSON（schema 1.0）。我把它想成「考卷题目 + 阅卷备忘」：

```text
样本
 ├─ 标识：版本、sample_id、修订号、语言
 ├─ 用户设定：年龄段、具体年龄
 ├─ 题目标签：场景类型、情绪极性
 ├─ 考题正文：history（多轮对话，末条必须是用户）
 ├─ 作答约束：target（固定短回复，不含标准答案）
 └─ 创作备忘：authoring（只给人看，不进模型）
```

### 谁看什么

| 区块 | 谁用 | 干什么 |
|---|---|---|
| sample_id / revision | 工程和版本管理 | 追踪、改版 |
| 年龄段 / 具体年龄 | 写作和评测 | 语言、细节是否贴龄 |
| 场景类型 / 情绪极性 | 切片统计 | 控覆盖、出报告 |
| history | **模型只看这个** | 真正的上下文 |
| target | 阅卷提醒 | 短回复、陪伴者视角；没有标准答案 |
| authoring | 人 | 背景、前文依赖、合理方向、禁止写法、红线、审核状态 |

### history 的硬规则

这些不是文风偏好，是产品约束：

- 6～12 轮，推荐 7 轮。
- 用户和陪伴者严格交替；最后一句必须是用户。
- 奇数轮从用户起；偶数轮允许从陪伴者起（表示截取自更长对话）。
- 用户单轮不超过 500 字，陪伴者不超过 200 字。
- 末轮之后才是模型要补的那句——**样本里不写答案。**

### authoring 里我放什么

| 字段 | 我用它记什么 |
|---|---|
| situation_summary | 故事背景，方便写作时记住「这件事怎么来的」 |
| context_dependencies | 回答时至少要照顾到的前文信息 |
| valid_response_directions | 至少两种合理接法，保证不是唯一答案题 |
| forbidden_response_patterns | 明确禁止的写法，比如直接给建议、空喊热情 |
| human_only | 红线必须打开 |
| review_status | 草稿 → 一审 → 双人复核 → 通过 |
| notes | 选题来源：分类、机制、scene id |

正式字段定义在 `schema/schema_v1.json`，示例在 `schema/sample_example_v1.json`。

## 6. 设计怎么落到构造台上

对外交付是两层：**数据源**（JSON / JSONL）+ **可视化构造台**（改数据）。开发者可以只读文件；要改选题库，请走本地服务，别双击 HTML。

```bash
node scripts/dev-server.mjs
# 浏览器打开终端提示的地址；页眉应显示「已连接仓库 JSON」
```

此时场景增删改会写回 `data/scenes/scene_library.json`。若直接用 `file://` 打开，改动只进浏览器 localStorage，页眉会显示「仅本地缓存」。

写对话时的流程：

1. 先选年龄段，只露出这个年龄用得上的事。
2. 从场景库挑一条生活事件（能搜分类、机制、事件，也能自己增删改）。
3. 工具自动带上编号、场景类型、情绪默认值、故事背景等。
4. 写对话：可以手写，也可以让模型续写或批量生成；机器稿默认进待审。
5. 过一遍本地规则检查（轮数、交替、字数、年龄锁、编号冲突等）。
6. 人工确认后，才算完成，才能导出到对话成品。
7. 用场景分布面板盯各类写了多少，别老挑同一类题。

状态大致是：

```text
草稿 → AI 待审 → 人工确认（可导出）
```

写的时候我反复跟自己说三句：

- 机制要贯穿前文，末轮才是考点。
- 说话方式要像这个年龄的人。
- 先接住，再决定要不要继续参与；别用统一热情盖过去。

## 8. 我刻意做的取舍

这些是我主动选的，不是做着做着变成这样：

1. **测接住，不测讲道理。** 所以没有参考答案，只有合理方向和禁止模式。
2. **事件优先于情绪词。** 所以先有场景库，再有对话。
3. **短回复。** 对齐产品形态；长篇咨询腔不应该靠字数赢。
4. **先消极起底，再平衡。** 基础层先铺「难受时会被怎样对待」；扩展和平衡再补正情绪与日常相处。否则产品只会急救，不会陪伴。
5. **身体与能量刻意加厚。** 生理期、身体羞耻、感官这些又高频又容易翻车；对外切片时建议单独看。
6. **红线走独立通道。** 隐私、依赖、关系替代，必须人审。
7. **样本里不写载体人设。** 我不把玩具性格塞进评测字段；评的是陪伴能力本身。
8. **年龄硬锁，不做假笛卡尔积。** 每条事件必须带有效 `ageBands`；候选卡 = 事件 × 允许年龄，并由规则审计情景匹配度（如尿床不上初中以上）。不适龄组合从正式待审剔除；比例不够就补真跨年龄事件，不恢复伪负样本。

## 最后一句

我用「生活大类 → 机制 → 原子事件」搭选题骨架，用「事件 × 允许年龄」的硬锁代替假笛卡尔积，再用「有前文、无标准答案、短回复接住」的多轮对话当考题。场景库管覆盖与年龄真实，人工确认管质量，红线题管安全。
