# 场景覆盖报告

这份说明讲两件事：测试集是怎么做出来的，以及场景库的覆盖大概长什么样。

数字以仓库选题库为准：`data/scenes/scene_library.json` 现为 **561** 条（每条带 `ageBands` 硬锁；合法卡片是审查后的年龄组合，不是场景 × 7 的笛卡尔积）。下文部分表格仍按早期「基础 200 + 扩展 190 = 390」切片统计；读数时请对照最新选题库。已经写好的对话成品很少，附录里单独说明，不拿它当整体分布。

---

## 一、我们要测什么

测的是：面对 3～35 岁用户、用中文聊天的情感陪伴能力。

做法很简单——不给标准答案。每条样本是一段多轮对话，最后一轮停在用户说话，留下一个「最需要被接住」的情绪或关系信号，让模型接着回。期望回复短一点：一两句到三句，尽量不超过四十个字。

选题来自生活事件库（`data/scenes/scene_library.json`）。先定一件具体发生的事，再写成对话。机器可以帮忙起草，但进正式测试集的，只收人工确认过的稿，发布在 `data/releases/`。

合法评测卡不是「每条事件 × 七档年龄」全铺开，而是审查情景与年龄匹配后的组合（例如实际尿床只留在约 3–11 岁）。详见 [数据集设计说明.md](数据集设计说明.md) §4.3。

## 二、怎么做出来的

### 给开发者的两条路径

| 路径 | 做什么 | 怎么开始 |
|---|---|---|
| 只用数据源 | 读 JSONL / 选题库做评测或对接 | 见根目录 [README.md](../README.md) |
| 可视化改数据 | 增删改场景、写多轮对话、待审导出 | `node scripts/dev-server.mjs` 后打开构造台 |

推荐用本地服务打开构造台；页眉显示 **已连接仓库 JSON** 时，场景改动会写回 `data/scenes/scene_library.json`。直接双击 HTML（`file://`）只会进浏览器 localStorage，不要当正式落盘。

### 构造台里的写作顺序

1. 先选年龄段（幼儿园到职场人，共七档）。场景库只露出这个年龄用得上的事。
2. 从场景库挑一条生活事件。每条事件挂着「分类」和「机制」（比如分离与想念、被排除与落单）。也能搜索、筛选，以及自己增删改场景。
3. 工具会自动带上样本编号、场景类型、情绪倾向、故事背景等。
4. 写对话：一般写 7 轮，允许 6～12 轮。可以手写，也可以让模型续写或批量生成；机器出的稿默认进「待审」。
5. 过一遍本地规则检查（轮数、角色交替、字数等）。
6. 人工点确认后，才算最终完成，才能进导出。
7. 用「场景分布」看各类写了多少，避免老挑同一类题。

几个写对话时坚持的原则：

- 先有具体事件，再写感受；机制要贯穿前文，别写成空喊情绪。
- 最后一轮用户话是考点，后面不要再写陪伴者答案。
- 要的是陪伴，不是心理咨询：别一上来给建议，别一味热情盖过去，别说教、别连珠炮追问。
- 说话方式要像这个年龄的人。
- 碰到隐私、过度依赖、想用人工智能替代真人关系这类红线，必须更谨慎，建议人审。

对话形式上的硬要求：用户和陪伴者一轮一轮交替说；最后一句必须是用户；用户单轮不超过 500 字，陪伴者不超过 200 字；期望模型回的那句，控制在 1～3 句、四十个字以内。

## 三、一条样本里有什么

可以把它想成一张「考卷题目」：

| 内容 | 干什么用 |
|---|---|
| 样本编号、修订号 | 方便追踪、改版 |
| 语言 | 固定简体中文 |
| 年龄段、具体年龄 | 决定口吻和生活细节 |
| 场景类型 | 这条主要考哪一类陪伴情境 |
| 情绪倾向 | 积极 / 消极 / 混合 / 中性，看最后一轮用户话 |
| 对话历史 | 真正喂给模型的上下文 |
| 回复形态要求 | 提醒阅卷：短回复、陪伴者视角 |
| 写作备注 | 背景故事、前文依赖、哪些回应算接住了、哪些写法要禁止、是否红线、审核状态 |

阅卷时：模型只看对话历史；写作备注给人看，不进模型。没有唯一标准答案。字段细节见 [schema字段说明.md](schema字段说明.md)。

年龄段怎么切：

| 年龄段 | 大概几岁 | 写样本时常用的具体年龄 |
|---|---|---:|
| 幼儿园 | 3～5 | 4 |
| 小学低年级 | 6～8 | 7 |
| 小学高年级 | 9～11 | 10 |
| 初中 | 12～14 | 13 |
| 高中 | 15～17 | 16 |
| 大学 | 18～21 | 20 |
| 职场人 | 22～35 | 28 |

场景类型这块，构造台里有 35 种叫法，字段规范里目前正式认 23 种。多出来的（比如身体成长羞耻、感官差异、节日记忆触发等）先能用来写，冻结正式版之前要把两边对齐。

### 4. 按年龄

基础 200 条在源数据里是「一条事件对应一个年龄」：

| 年龄 | 条数 | 占比 |
|---|---:|---:|
| 幼儿园 | 20 | 10% |
| 小低 | 20 | 10% |
| 小高 | 24 | 12% |
| 初中 | 26 | 13% |
| 高中 | 24 | 12% |
| 大学 | 30 | 15% |
| 职场人 | 56 | 28% |
| 合计 | 200 | 100% |

扩展 190 条不是这样标的：一条事件往往适配好几个年龄段（比如「学龄」「青春期」「生理期相关」），所以不能和上表简单相加。工具里会按当前选的年龄段自动过滤。

### 5. 机制上都在考什么（举例）

基础里出现较多的：被排除与落单、物品与隐私边界、结果与去向等待、分离与想念、关系疏远、进步与分享被敷衍、高期待与条件式认可等。

扩展里出现较多的：身体成长与羞耻、生理期相关一系列（疼痛、侧漏、用品、污名、隐私被侵等）、青春期身体变化与隐私、正情绪小声分享等。

### 6. 读这些数字时注意

- 身体与能量差不多占了三成，是刻意加厚的；对外报数或切片评测时，建议能单独拎出来看。
- 基础层职场人占到近三成，也是故意的：成年关系、边界、压力更密。
- 数字生活、日常微挫败扩得少；低龄不适用的格子空着，不算漏做。
- 构造台和字段规范对「场景类型」还没完全对齐，正式冻结前要收拾干净。
- 只有写回 `data/scenes/scene_library.json` 的改动才算进仓库默认库。经 `dev-server` 保存会自动落盘；`file://` / localStorage 里的改动不会进这张表。当前仓库默认库以 JSON 文件为准（561 条）；上表部分切片仍按早期 390。

## 五、正式评测时怎么用

1. 把对话历史交给待测模型，停在用户最后一句。
2. 让模型用陪伴者身份回一句短话（建议一两句到三句，四十个字以内）。
3. 人来看：有没有接住这件事和此刻的情绪；有没有踩到「直接给建议、空喊热情」这类禁止写法。
4. 红线题必须人审，先看边界和安全，再看暖不暖。

一句话：我们测的是「能不能接住」，不是「会不会讲大道理」。

## 七、接下来建议怎么推进

1. 按场景分布面板，把各类、各年龄都铺开，别老写分离孤独。
2. 身体与能量体量大，单独盯占比；红线和正情绪也单独看完成率。
3. 场景类型命名和字段规范对齐后再锁版本。
4. 正式测试集只收人工确认稿，发布进 `data/releases/`。
5. 改选题库请用 `node scripts/dev-server.mjs`（页眉「已连接仓库 JSON」）；落盘后再更新这张分布表。无服务时可用 `node scripts/export-scene-library.mjs` 作备选导出。
