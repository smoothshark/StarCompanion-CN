# 目录与文件说明

这份文档回答三个问题：文件是做什么的、从哪里来、能不能直接修改。

## 一眼判断

| 路径前缀 | 含义 | 默认操作 |
|---|---|---|
| `app/` | 产品审查工具 | 打开和使用 |
| `data/` | 可发布、可版本化的数据 | 谨慎修改并评审 |
| `docs/` | 产品与数据设计文档 | 设计变化时同步更新 |
| `schema/` | 程序可读的数据契约 | 变更需兼容性评审 |
| `scripts/` | 开发和数据流水线 | 开发者维护 |
| `workspace/` | 本机运行状态和中间结果 | 不发布，可恢复或归档 |

## 根目录

| 文件 | 用途 | 是否手改 |
|---|---|---|
| `README.md` | 项目总入口，给产品和开发指路 | 是 |
| `CONTRIBUTING.md` | 数据修改、人审、发布和禁止提交规则 | 是 |
| `LICENSE` | 数据与工具代码许可 | 很少 |
| `CITATION.cff` | 论文、报告或产品引用信息 | 发布版本时 |
| `.gitignore` | 排除本地运行产物、日志和密钥 | 开发维护 |

## app

| 文件 | 用途 | 来源 | 是否手改 |
|---|---|---|---|
| `app/index.html` | 场景管理、卡片写作、待审、确认、导出和覆盖分析页面 | 产品工具源码 | 改页面功能时可以 |
| `app/assets/pending-review.generated.js` | 把全部机器待审卡片加载进页面 | 批量脚本从 checkpoint 生成 | 不建议，重新合并会覆盖 |
| `app/README.md` | 产品入口和数据加载说明 | 人工维护 | 是 |

## data

| 文件 | 用途 | 来源 | 是否手改 |
|---|---|---|---|
| `data/README.md` | 数据区总说明和数据流 | 人工维护 | 是 |
| `data/scenes/scene_library.json` | 561 条原子事件主库，包含年龄硬锁、场景类型和默认情绪 | 产品工具或人工维护 | 优先通过页面修改 |
| `data/scenes/README.md` | 场景字段与维护方法 | 人工维护 | 是 |
| `data/releases/approved_v0.1.jsonl` | 早期 v0.1 对话版本，共 3 条 | 人工整理 | 只在发布流程中改 |
| `data/releases/README.md` | 正式版本命名与发布规则 | 人工维护 | 是 |
| `data/sources/mindmap/events-core.json` | 基础事件源的核心场景 | 人工策划 | 是 |
| `data/sources/mindmap/events-boundary.json` | 基础事件源的边界与高风险场景 | 人工策划 | 是 |
| `data/sources/mindmap/events-remaining.json` | 基础 200 条中的其余事件 | 人工策划 | 是 |

`data/` 中没有模型日志、checkpoint 或临时批次。看到这里的文件，应当可以解释其版本和发布含义。

## scripts

| 文件 | 用途 | 会写什么 |
|---|---|---|
| `scripts/dev-server.mjs` | 托管 `app/` 并提供场景库读写 API | `data/scenes/scene_library.json` |
| `scripts/generate-a1-batch.mjs` | 调用 SiliconFlow 并发生成或续跑 | `workspace/state/`、`workspace/review/`、`app/assets/` |
| `scripts/a1-codex-batch-tools.mjs` | 准备 Codex 批次、合并、统计和审计 | `workspace/`、`app/assets/` |
| `scripts/run-a1-codex-cli.mjs` | 并发执行准备好的 Codex manifests | `workspace/runs/codex/` |
| `scripts/export-scene-library.mjs` | 从页面内嵌库导出场景 JSON | `data/scenes/scene_library.json` |
| `scripts/export-schema-examples.mjs` | 每个 `scene_type` 抽取 2 条真实待审样例 | `schema/sample_example_v1.json` |
| `scripts/generate-a1-mindmap.mjs` | 生成基础思维导图派生文件 | `workspace/derived/` |
| `scripts/build-a1-authoring-html.mjs` | 从模板重建基础离线页面 | `app/index.html` |
| `scripts/templates/dialogue-authoring.template.html` | 基础页面模板 | 由构建脚本读取 |
| `scripts/README.md` | 脚本索引和常用命令 | 不写数据 |

## workspace

`workspace/` 是本机工作区。这里的大文件默认被 Git 忽略。

| 路径 | 用途 | 处理建议 |
|---|---|---|
| `workspace/review/pending-review.jsonl` | 全部待审卡片的分析友好导出 | 保留到人审完成 |
| `workspace/state/batch-checkpoint.ndjson` | 批量任务主检查点 | 续跑期间必须保留 |
| `workspace/state/batch-progress.json` | 最近一次任务进度和分布 | 可重新生成 |
| `workspace/state/batch-failures.ndjson` | API 失败记录 | 排错和重试后可归档 |
| `workspace/runs/codex/<批次>/run.json` | 一次批量任务清单 | 验收后归档 |
| `workspace/runs/codex/<批次>/manifests/*.json` | 每个子批次的输入 | 验收后归档 |
| `workspace/runs/codex/<批次>/results/*.ndjson` | Codex 返回结果 | 合并确认前保留 |
| `workspace/runs/codex/<批次>/logs/*.log` | 单批运行日志 | 排错用 |
| `workspace/runs/codex/<批次>/merge-report.json` | 合并结果和失败摘要 | 建议随批次保留 |
| `workspace/derived/` | 可重新生成的思维导图等派生文件 | 不作为正式数据 |
| `workspace/README.md` | 本地工作区说明 | 人工维护 |
| `workspace/RUNS.md` | 九次 Codex 历史运行的用途与结果索引 | 人工维护 |

## 卡片从生成到发布

1. `data/scenes/scene_library.json` 定义原子事件和年龄范围。
2. 生成脚本把机器稿写入 `workspace/state/batch-checkpoint.ndjson`。
3. 合并脚本同步生成页面数据和 JSONL 工作导出。
4. 产品在 `app/index.html` 中逐张审查、修改和确认。
5. 只有最终确认稿才整理进 `data/releases/approved_vX.Y.jsonl`。

任何位于 `workspace/` 或文件名含 `pending-review.generated` 的内容，都不能直接宣称为人工确认数据。
